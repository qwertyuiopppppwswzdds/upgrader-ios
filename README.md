# Upgrader iOS — GitHub Actions

Этот проект подготовлен для сборки на GitHub Actions с Windows-компьютера.
Xcode на твоём ПК не нужен: GitHub запускает macOS runner и собирает приложение там.

## 1. Создать репозиторий

На GitHub создай новый репозиторий, например `upgrader-ios`.

Распакуй содержимое этого архива и загрузи **все файлы** в репозиторий.

Структура должна выглядеть примерно так:

```text
upgrader-ios/
├── .github/
│   └── workflows/
│       └── build.yml
├── UpgraderIOS/
├── UpgraderIOS.xcodeproj/
└── README.md
```

## 2. Запустить сборку

На странице репозитория:

1. Открой **Actions**.
2. Выбери **Build iOS IPA**.
3. Нажми **Run workflow**.
4. Дождись окончания.
5. Открой завершившийся запуск.
6. В разделе **Artifacts** скачай `UpgraderIOS-unsigned-ipa`.

## ВАЖНО: почему скачанный IPA не сразу устанавливается

Эта workflow специально делает **unsigned IPA**. Он полезен для проверки сборки, но iPhone не установит его как обычное подписанное приложение.

Для установки на реальный iPhone IPA должен быть подписан Apple-сертификатом и provisioning profile.

### Вариант A — Apple Developer

Можно добавить сертификат/профиль в GitHub Secrets и изменить workflow на signed build.

Понадобятся:
- Apple Developer account;
- distribution/development certificate;
- provisioning profile;
- секреты GitHub для сертификата и профиля.

### Вариант B — личная подпись

Для личного устройства можно использовать инструменты вроде AltStore/SideStore после получения подходящей сборки. Это отдельный этап от самой компиляции.

## Что уже находится в приложении

- 4430 предметов из базы исходного XAPK;
- апгрейд;
- расчёт шанса;
- инвентарь;
- магазин;
- покупка/продажа;
- поиск;
- история;
- локальное сохранение.

Это именно восстановленная iOS-реализация, а не конвертация Android APK.

## Если GitHub покажет ошибку Xcode project

Открой лог failed job и пришли его сюда — по логу можно исправить конкретную ошибку проекта.
